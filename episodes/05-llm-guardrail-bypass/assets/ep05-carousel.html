Two defenses couldn't even run

Reported honestly as NOT EVALUATED, never guessed. Each failure is a finding.
Not evaluated
Guardrails' prompt-injection validator
Built on Rebuff, which phones an LLM to score each request. It needs network egress. In an air-gapped deployment it simply cannot run.
Not evaluated
Meta Llama Guard 4  (12B)
The flagship. generate() failed through a Llama4-vs-transformers incompatibility that reproduced on both GPU and CPU. It would not run to completion.
The newest, most-hyped guard is the one that wouldn't start. The "prompt-injection" validator can't work without the internet. Benchmark scores don't matter if the tool won't run where you deploy it.

Don't trust the front door

The input classifier is bypassable by construction. It never tokenizes the world the way your model does. So move your real controls to the exit:
→
Output-side secret / DLP scanning. Catch the leak on the way out, even when the attack was invisible on the way in.
→
Canary tokens on sensitive values, so a leak trips an alarm.
→
Least privilege behind the guard, so a caught injection reaches nothing worth stealing.
→
Normalize before you classify as hardening. Strip the hidden characters so the guard sees what the model sees.
The dumb exit scan is what saved every case. Build that first.
